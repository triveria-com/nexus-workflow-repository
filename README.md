# nexus-workflow-repository

Public repository of Triveria NEXUS Workflows.

Each workflow is a single Markdown file with YAML frontmatter, stored under
[`workflows/`](workflows/). The repository is published to GitHub Pages as a
small static site: a homepage listing every workflow, and a per-workflow page
that renders the frontmatter (title, summary, questions) and the Markdown body.
Each workflow page has an **Import to NEXUS** button that opens the workflow
directly in the NEXUS environment selected from the dropdown in the header
(Dev or Public Test).

## Adding a new workflow

1. Add a new `workflows/<slug>.md` file, following the frontmatter shape in
   [`workflows/pcf-workflow.md`](workflows/pcf-workflow.md) (`slug`, `title`,
   `summary`, and an optional `questions` list).
2. Push to `main`. The `Deploy GitHub Pages` GitHub Action regenerates
   `workflows/data.json` (the file the site fetches at runtime) and publishes
   the site automatically.

## Wallet and credential templates

This repository is the source of truth for the wallet configuration templates and
the credential templates used across Triveria NEXUS: tw-web-app (create wallet from
template, credential forms), the nexus-ai-backend knowledge base and the `twt` CLI.
Change a template here and nowhere else. The consumers are switching over to read
from here in [#1](https://github.com/triveria-com/nexus-workflow-repository/issues/1).

### Layout

| Kind | File | Identified by |
|---|---|---|
| Wallet | `wallets/<framework>/…/<slug>.json` | its path without `.json`, e.g. `noop/triveria_org` |
| Credential | `credentials/<slug>.json` | its `credentialTypeId`, e.g. `urn:triveria.io:id:1` |

- **Wallet templates** have a `name`, an optional `description`, and the wallet `config`
  sent to the wallet create call. Some also carry `localWalletData`, which is used by
  tw-web-app only. The top-level folder is the trust framework of `config.trustFramework`,
  lowercased (`ebsi`, `eudi`, `idtl`, `noop`), and may have subfolders.
- **Credential templates** have a `credentialTypeId`, `name`, `format`, optional
  `description`, `schema` and display hints, and a `subjectDefinition` whose `form` and
  `display` are JSON documents serialized into strings.
- **Credential file names** are derived from the type id: lowercased, with every run of
  characters other than `a-z` and `0-9` replaced by `-`. So `urn:triveria.io:id:1` is
  `credentials/urn-triveria-io-id-1.json`. Type ids contain `:` and `,`, which are not
  valid in file names everywhere. A derived name also lets a consumer find a template
  from its type id alone.

### Published URLs

The deploy publishes every template at its path, plus an index of each kind:

- https://workflows.nexus.triveria.io/wallets/index.json: `id`, `framework`, `name`,
  `description` and `path` of every wallet template
- https://workflows.nexus.triveria.io/credentials/index.json: `credentialTypeId`,
  `format`, `name`, `description` and `path` of every credential template
- `https://workflows.nexus.triveria.io/<path>`: a template itself, e.g.
  https://workflows.nexus.triveria.io/wallets/noop/triveria_org.json

The indexes are generated by the build and not committed. To read a template at a
specific commit, build its path from the id or the type id and fetch it from
`https://raw.githubusercontent.com/triveria-com/nexus-workflow-repository/<commit>/<path>`.

### Adding or changing a template

1. Add or edit the JSON file following the layout above.
2. Run `npm run validate`. The same checks run on every pull request, and the deploy
   refuses to publish an invalid template.

Templates are checked for structure: valid JSON, the required properties, the trust
framework folder and the credential file name. Whether the wallet service accepts a
wallet config is not checked here. Once twt reads from here, its `twt liveness` check
in the dev and prod pipelines will create wallets from the NOOP templates and catch that.

## Local preview

```sh
npm install
npm run build      # generates workflows/data.json and the template indexes
npx serve .         # or any static file server; open the printed URL
```

## One-time repository setup

In **Settings → Pages**, set "Build and deployment" → **Source** to
**GitHub Actions**. The included workflow at
[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml)
handles the rest on every push to `main`.
